# 飞蝗产卵行为自动分析工具 · 使用说明

上传视频 → 自动输出每段产卵的起止时刻与时长。

---

## 这个工具能做什么

**输入**：飞蝗产卵实验的录像（mp4/avi/mov/mkv）
**输出**：每个视频的产卵起点、终点、时长，可导出 CSV

**验证精度**（12 个视频对照人工标注）：

| 指标 | 平均绝对误差 | 中位数 |
|------|-------------|--------|
| 产卵起点 | 2.3 分钟 | 1.1 分钟 |
| 产卵终点 | 5.0 分钟 | 3.6 分钟 |
| 产卵时长 | 6.1 分钟 | 3.2 分钟 |

检出率 12/12，其中 10 个视频起点误差 ≤ 1.4 分钟。

---

## ⚠️ 适用范围与限制

**适用**：静止型长时程行为。工作原理是「检测飞蝗 → 追踪个体 →
识别长时间不离开原地的时段」，产卵恰好具备这一特征。

**不适用**：精细动作的区分。曾尝试用同一套轨迹特征区分
探索 / 产卵 / 清洁三种行为，macro F1 仅约 0.5（三分类随机为 0.33），
其中探索有 62% 被误判为产卵。原因是检测框不包含
「腹部是否插入沙中」这一关键信息。若需区分精细动作，
需升级到关键点姿态估计（YOLO-pose）。

**已知局限**：
- 探索期若长时间原地停留，产卵起点可能被判早（实测最差 -17.5 分钟）
- 产卵末期若追踪丢失，终点可能偏早（实测最差 -17.2 分钟）
- 未检出产卵的视频建议人工复核，可能是真未产卵，也可能是漏检

## 环境准备

依赖 `ultralytics`、`opencv`、`gradio`。若已有分析环境，只需补装 gradio：

```bash
pip install gradio
```

从零搭建见 `ENV_SETUP.md`（海光 DCU 环境有特殊要求，勿直接 `pip install torch`）。

---

## 启动

```bash
# 本机使用
python app.py

# 指定权重路径
python app.py --weights path/to/best.pt

# 允许局域网内其他机器访问
python app.py --host 0.0.0.0

# 生成临时公网链接（供外部协作者使用，72 小时有效）
python app.py --share
```

启动后浏览器打开 `http://127.0.0.1:7860`。

---

## 使用步骤

1. **上传视频**（可多选，支持批量）
2. **确认权重路径**（默认 `runs/detect/runs/v2/weights/best.pt`）
3. 点 **开始分析**
4. 结果显示在右侧表格，点 **下载结果 CSV** 保存

首次分析每个视频需数分钟（检测 + 追踪）；启用「轨迹缓存」后，
同一视频再次分析或调整参数时秒级完成。

---

## 参数说明

一般无需改动，默认值是在 12 个视频上验证过的定版参数。

| 参数 | 默认 | 何时调整 |
|------|------|---------|
| 最短产卵时长 | 15 分钟 | 若实验中产卵普遍更短，可调低；调低会增加误检 |
| 检测置信度 | 0.7 | 漏检多时调低；误检多（框到沙子/反光）时调高 |
| 抽帧率 | 1 帧/秒 | 产卵是慢行为，1 fps 足够。调低更快但精度略降 |
| 轨迹缓存 | 开启 | 关闭则每次重新推理，仅在更换模型后需要 |

## 结果解读

CSV 包含五列：

| 列 | 含义 |
|---|---|
| 视频 | 文件名 |
| 结果 | `产卵` / `未检出` / `出错` |
| 产卵起点 | 时:分:秒 |
| 产卵终点 | 时:分:秒 |
| 产卵时长(分钟) | 终点 − 起点 |

**「未检出」不等于「没产卵」**——也可能是漏检（如产卵时长不足阈值、
追踪失败）。作为科学数据使用前建议人工复核这部分视频。

## 常见问题

**Q：提示模型加载失败**
检查权重路径。若在 HPC 上运行，确认已激活环境（`locust-env`），
未激活时会报 `libssl.so.1.1` 或 `ModuleNotFoundError`。

**Q：分析很慢**
确认在有 GPU/DCU 的节点上运行。登录节点无加速卡，会退回 CPU，慢数十倍。
HPC 上建议用 `sbatch` 提交批量分析，而非在界面里跑大批视频。

**Q：某个视频结果明显不对**
用 `export_clips.py` 导出该视频产卵起止点前后的带框片段，人工核对：

```bash
python scripts/export_clips.py --weights <权重> --video <视频> \
    --results <结果csv> --out clips
```

**Q：想批量处理几十个视频**
界面适合少量视频和交互式核对。大批量用命令行更稳（不受浏览器断连影响）：

```bash
python scripts/detect_oviposition.py --weights <权重> --video-dir <目录> \
    --cache-tracks track_cache --out results.csv \
    --win-sec 180 --frag-min-duration 900 --stitch-gap 60 --stitch-dist 100
```
